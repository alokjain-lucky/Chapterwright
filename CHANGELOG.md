# Changelog

All notable changes to Chapterwright. See [README.md](README.md#changelog) for the most recent entries — this file is the full history.

### 2.5.0

- **Added estimated reading time to each chapter**, shown in the chapter eyebrow next to the chapter number (e.g. "Chapter 3 · 6 min read"). `hsrtech_reading_time()` (`public/reading-time.php`) had existed since early on but was never actually wired up anywhere — this was the first real caller.
- **Added Gutenberg block transforms to the Code Snippet block**: a `core/code` block or a `core/paragraph` containing code can now be converted straight into `chapterwright/code-snippet` via the block toolbar's "Transform to" control (`blocks/code-snippet/edit.js`). A shared `toPlainText()` helper strips rich formatting and converts `<br>` to real newlines regardless of whether the source attribute is a plain string or a `RichTextData` instance; the transformed block defaults to `language: 'text'` rather than guessing.
- **Fixed the mobile navigation menu not opening at all** on any book/chapter/archive page. Root cause: `templates/partials/document-start.php` called `wp_head()` *before* rendering the header template part, so the Script Modules API's import map (needed to resolve core/navigation's `@wordpress/interactivity` dependency) printed before that dependency had even been registered — the browser then rejected the bare module specifier outright when the header's own view script tried to load later. Fixed by capturing the header markup via output buffering before `wp_head()`, then echoing it after `<body>` opens, reproducing the registration order a normal block-theme page guarantees. Root-caused and verified live via the console error, and by confirming the toggle's click handler now correctly adds `is-menu-open`.
- **Fixed mobile-viewport layout issues** reported from a real phone screenshot: the book title and "X of Y" chapter counter now stack vertically instead of colliding when the title wraps to two lines (`.hsrtech-reader__bar`); increased top padding on the reader view below 782px, since the site header can wrap onto two rows there and the existing mobile padding left almost no air beneath it.
- **Fixed the reading-progress bar at the top of the page ignoring the book's accent color.** It sat as a DOM sibling *before* `<main>` in `templates/single-hsrtech_chapter.php`, so the `--hsrtech-accent` custom property (only ever declared inline on `<main>`) never reached it, and it silently fell back to a hardcoded red-orange on every book regardless of that book's own accent. Moved it to be the first child *inside* `<main>` instead — no visual change, since it's `position: fixed`, only what CSS variables it can see. Verified live against a book using a non-default accent color.
- **Added previous/next chapter prefetching** for faster in-book navigation: `public/prefetch.php` (new) hooks into `wp_head` and prints `<link rel="prefetch">` for the adjacent chapters' permalinks, so clicking "Previous"/"Next" is typically served from cache. Extracted the shared "find this chapter's neighbors in an ordered list" logic into `hsrtech_locate_chapter()` (`includes/queries.php`) so the prefetch hint and the chapter template's own prev/next navigation can't independently drift apart.
- **Accessibility pass**, verified live rather than assumed: `templates/archive-hsrtech_book.php` (the `/books/` library page) gained the skip link and landmark `id`/`tabindex="-1"` the other two templates already had, plus a visually-hidden fallback `<h1>` (new `.hsrtech-sr-only` utility class) for when a site owner clears the visible heading text in Settings, so screen-reader heading navigation still has something to land on. `templates/partials/toc-list.php`'s draft-chapter row no longer hides its "Draft" badge from screen readers — it was wrapped in `aria-hidden="true"`, copied from the published-chapter case where hiding the (list-order-redundant) chapter number is correct, but "Draft" is the only signal that row isn't a working link. Spot-checked contrast ratios for the core ink/muted/code-ink color pairs by calculation (all pass WCAG AA, 4.59:1–16.19:1).
- **Code-cleanliness audit**: cross-referenced every plugin function against its call sites (nothing dead), checked for duplicate CSS selectors, debug leftovers, and indentation drift (none found), and removed a stray empty `admin/app/src/components/` directory left over from early scaffolding.
- **Fixed the book cover image on `/books/` growing oversized with only one or two books.** `.hsrtech-book-card` had no `max-width`, so the grid's `auto-fit` columns — which correctly collapse empty tracks to let existing cards grow when there ARE enough books to matter — stretched a sparse row's card to the full container width, blowing up its `aspect-ratio: 4/5` cover into a huge, near-full-bleed image. Capped `.hsrtech-book-card { max-width: 420px; }`, matching how wide a card naturally lands once there are enough books for multiple columns. Verified live on this site's actual single-book library.

### 2.4.0

- **Fixed book/chapter meta silently failing to save**, at all, through any code path — `_hsrtech_accent`, `_hsrtech_subtitle`, `_hsrtech_book_id`, `_hsrtech_order`, `_hsrtech_section_id` and every other registered meta field. Root cause: neither `hsrtech_book` nor `hsrtech_chapter`'s `supports` array (`hsrtech_register_post_types()`, `includes/content-types.php`) included `'custom-fields'`, which `WP_REST_Posts_Controller::get_item_schema()` requires before it will add a `meta` property to a post type's REST schema at all. `register_post_meta()` still ran and the keys were genuinely registered, so nothing looked broken from that side — every `meta` value sent via the REST API was just silently accepted and silently discarded, with no error and no rejected write. Books "worked" only by coincidence: `_hsrtech_accent`'s sanitize callback happens to fall back to a real-looking color (`#f45d48`) on invalid input, masking the bug. Fixed by adding `'custom-fields'` to both `supports` arrays. One pre-existing chapter (ID 59) created before this fix remains orphaned (no `_hsrtech_book_id`) and was intentionally left untouched rather than deleted, since it has real content.
- **Added real syntax-token coloring, a language label, and a copy button to code blocks**, plus a floating "back to table of contents" button on chapter pages (new `show_toc_button` setting). A hand-rolled, dependency-free regex tokenizer (`assets/js/code-highlight.js`, one rule table per language: PHP/JS/CSS/HTML/Shell) replaces what was previously plain, uncolored code — the code-snippet block already had a language label and copy button, but no per-token coloring, and the plugin's own seed book content used the core Gutenberg Code block, which had none of the three. For plain Code blocks with no language metadata, `guessLanguage()` makes a conservative best-effort guess. Tokens are inserted via `textContent`/`createElement`, never `innerHTML`, so escaping is enforced by the DOM API.
- **Replaced the "back to table of contents" link with an in-page slide-in drawer** (`assets/js/toc-drawer.js`, `templates/partials/toc-list.php`) — progressive enhancement over a real `<a href="{book}#hsrtech-toc-eyebrow">`, so it still works with JS disabled. Marks the currently-open chapter with `aria-current="page"`. Extracted the book page's inline TOC-grouping logic into a shared `hsrtech_build_toc_sections()` (`includes/queries.php`) so the book page and the drawer can't drift out of sync. Split `assets/js/chapterwright-reader.js`'s single top-level scope into two independent IIFEs (color mode, reading-progress bar) so either feature keeps working correctly when the other's markup isn't present on a page.
- **Chapter reading-view typography overhaul**: moved from fluid `clamp()`-scaled sizes to a flat `1rem`/16px body size with tightened line-height (1.6) and proportionally re-tuned spacing throughout (paragraphs, headings, lists, blockquote, pre, callout, table). Added `text-wrap: balance` on headings, `text-wrap: pretty` + `hanging-punctuation: first` on paragraphs/list items/blockquotes, and accent-colored `li::marker`. Inline `<code>` went through three iterations before landing on a neutral ink-tinted background chip (`color-mix(in srgb, var(--hsrtech-ink) 8%, transparent)`, no border) — an initial-letter drop cap and a filled/outlined code style were both tried and then removed after live review found them too visually heavy.
- **Book and archive page typography pass**: book hero subtitle/description, the book-intro prose block, TOC section headings/descriptions, the archive header, and archive card title/excerpt moved to the same flatter, more tightly-spaced type scale as the chapter reading view, calibrated a step larger for hero/landing context.
- **TOC drawer trigger icon**: sized the SVG icon explicitly (it had no `width`/`height` and was falling back to an oversized default), and added a CSS-only tooltip ("Table of contents", via `data-tooltip`/`::after`, shown on hover/focus) for discoverability.
- **Added a "coming soon" flag for books**: new `_hsrtech_coming_soon` meta on `hsrtech_book`. Checking it in the admin app (`BookFields`, `admin/app/src/screens/book-detail.js`) auto-publishes an unpublished book in the same save request, since the admin app had no separate publish control; unchecking it never un-publishes. Front-end: `templates/book-grid.php` swaps the archive card's CTA and adds a "Coming soon" badge; `templates/single-hsrtech_book.php` shows the same badge and hides "Start reading".
- **Added a `show_draft_chapters` setting** (off by default) to optionally surface draft chapter titles in the table of contents. `hsrtech_get_chapters()` (`includes/queries.php`) gained an optional `$statuses` param so TOC rendering can fetch `array('publish','draft')` without affecting the `$chapters` variable that drives prev/next navigation and pagination — those never include drafts. A draft chapter renders as a non-clickable, dimmed row (`.hsrtech-toc-row-link--draft`) instead of a link, since its permalink would 404 or leak a preview URL for a logged-out visitor.
- **Added a book-completion progress bar** on the chapter reader/nav dividers — a gradient bar showing how far into the whole book the reader is (distinct from the existing scroll-position progress bar for the current chapter), computed in `templates/single-hsrtech_chapter.php` and exposed as a `--hsrtech-progress` custom property.
- **Fixed three CSS specificity bugs**, all found by live-testing rendered output and matching `document.styleSheets` rules against the actual DOM rather than by re-reading source: (1) `wp-content/themes/alok-jain/assets/css/books.css`'s light-theme block was missing a `--hsrtech-code-ink` override, leaving code text dark-on-dark in light mode; (2) `.hsrtech-toc-jump`'s own `color` lost to the `.hsrtech-page a { color: inherit; }` reset; (3) `.hsrtech-book-card__cover > span { color: #fff; }` (meant for the no-cover-image title placeholder) also matched the new "Coming soon" badge sitting alongside it, rendering it invisible — fixed by giving the placeholder its own dedicated class (`.hsrtech-book-card__cover-label`) rather than adding more specificity.

### 2.3.2

- Fixed newly created chapters sometimes not appearing in a book's chapter list. `getBookChapters()` (`admin/app/src/api.js`) used to query the core `/wp/v2/hsrtech_chapter` collection with `status` as an array and `context=edit`, fetching every chapter the current user could edit across every book, then filtering client-side by `_hsrtech_book_id` — reported as: add a chapter, save it, and it's not in the list. Replaced with a dedicated `GET /chapterwright/v1/books/{book_id}/chapters` route (`admin/rest/chapters.php`, `hsrtech_rest_get_book_chapters()`) that wraps `hsrtech_get_all_chapters_for_admin()` (`includes/queries.php`) — the same plain `get_posts()` query already trusted elsewhere in the plugin — instead of relying on the collection endpoint's own multi-status/context capability handling.
- Chapter rows in the admin app now match section rows: an always-visible status pill (previously only shown for non-published chapters), and explicit **Edit** / **Trash** buttons in place of the title being the only way into a chapter. Adding a chapter no longer opens the Block Editor in a new tab automatically.
- The block-editor sidebar's Chapter Details panel (`admin/app/src/editor-sidebar.js`) now shows a chapter's book, section, and order as read-only text with a link back to the admin app, rather than editable `SelectControl`/`TextControl` fields — reported as confusing since it looked like an unfilled "make a selection" control even for a chapter the admin app had already assigned correctly. Reassigning a chapter's book or section is now only done from the admin app's Book detail screen, which is book-wide-aware in a way this panel isn't.
- Updated the Chapter help tab (`admin/help.php`) to match: the Chapter Details panel is described as read-only reference information, not an editable control.

### 2.3.1

- Added `admin/redirects.php`: redirects the native Books/Chapters list-table screens (`edit.php?post_type=hsrtech_book`, `edit.php?post_type=hsrtech_chapter`) and "Add New" screens (`post-new.php?post_type=...`) to the `admin.php?page=chapterwright` admin app, hooked on `load-edit.php` / `load-post-new.php`. These post types register with `show_ui => true` but `show_in_menu => false` (since 2.0.0), so the native screens were still directly reachable by URL even though nothing in the plugin linked to them — landing on one showed the old, scattered pre-2.0.0 interface. Deliberately excludes `post.php?action=edit` (the Block Editor screen the admin app and editor sidebar both deep-link into for actual content) and the native Trash view (`post_status=trash` — used by the "View trashed books" link added in 2.3.0; the admin app does not reimplement restore/permanently-delete). No custom taxonomies exist in this plugin, so there was nothing else to redirect. Also corrected a stale claim in the Book help tab that accent color affects the "Start reading" button — it doesn't (see the 2.0.3 changelog entry, which fixed the same misconception in the admin app's own UI but missed this copy).

### 2.3.0

- Added the ability to delete a book from the admin app: a "Trash" button on each book card in **Books & Chapters** (`books-list.js`), and a "Danger zone" panel with a "Move book to Trash" action on a book's own detail page (`book-detail.js`). Both call the existing `trashBook()` (`api.js`), which was defined back in 2.0.0 but never actually wired to any button. Trashing a book only moves the `hsrtech_book` post to trash (a plain `DELETE` without `force`) — it does not cascade to the book's sections or chapters, matching how `hsrtech_delete_book_sections()` is documented to only run on permanent delete, not trash. A "View trashed books →" link on the books list opens WordPress's native Trash list for the post type (`edit.php?post_type=hsrtech_book&post_status=trash`), where a book can be restored or permanently deleted — the admin app does not reimplement that screen. Sections and chapters already had delete/trash actions since 2.0.0; this was the one remaining gap.

### 2.2.1

- Fixed the **Books & Chapters** admin menu item disappearing after updating to 2.2.0, leaving only **Settings** visible. Root cause: `hsrtech_maybe_upgrade()` (which calls `hsrtech_add_capabilities_to_roles()`) ran on the `plugins_loaded` hook, but Books/Chapters only register as post types on `init` — which always fires after `plugins_loaded`. `get_post_type_object()` returned `null` at that point, so the capability grant silently did nothing, while `hsrtech_db_version` still advanced to `2.2.0` as if it had succeeded, meaning the block would never run again on that site. Fixed by moving the upgrade hook to `init` priority 20 (after `hsrtech_register_post_types()`'s default priority 10), and adding a `2.2.1` version gate that re-runs the grant once to repair any site that already hit the bug — no manual action needed, it self-heals on the next page load.

### 2.2.0

- Books and Chapters now register their own `capability_type` (`hsrtech_book`/`hsrtech_books`, `hsrtech_chapter`/`hsrtech_chapters`, both with `map_meta_cap => true`) instead of the generic `post`/`posts` capabilities every custom post type gets by default. `hsrtech_add_capabilities_to_roles()` grants Administrator, Editor, Author, and Contributor exactly the access they already had under the old generic behavior (mirroring WordPress's own default role grants for the `post` type), so this is a no-op for every existing site unless it deliberately creates a new, narrower role. Runs on activation and, for sites updating in place, on the next request via `hsrtech_maybe_upgrade()`. Uninstalling removes every granted capability from every role, including custom ones. See "Capabilities and roles" in README.md.

### 2.0.1

- Fixed a critical bug in the 2.0.0 admin app: every custom `chapterwright/v1` REST route (sections and chapter reordering) fataled on every request with `is_numeric() expects exactly 1 argument, 3 given`, because WordPress calls a route's `validate_callback` with three arguments and `is_numeric()` is a PHP built-in that doesn't accept extras. Opening a book in the admin app was the most visible symptom. Fixed by wrapping the check in a plain function instead of passing the built-in directly.
- Fixed the **Settings** page rendering blank: it's registered as a submenu of the "Chapterwright" top-level page, but was doing so before that top-level page had actually been registered (a file-load-order accident), so WordPress computed the wrong internal hook name and never called the page's render function. Fixed by giving the top-level menu registration an earlier `admin_menu` priority. This also fixes the sidebar order — **Books & Chapters** now consistently appears above **Settings**.
- Refreshed the admin app's visual design: a proper page header, consistent panel styling and spacing, status pills for draft/pending/private items, cleaner section/chapter rows, and modern (40px) form control sizing throughout.
- **Uninstalling the plugin now performs a full clean sweep** instead of retaining content: every Book and Chapter (and their metadata), the `hsrtech_sections` table, and the plugin's settings are all permanently deleted when you remove Chapterwright from the Plugins screen. This replaces every earlier version's "retain content" behavior — see "Updating and uninstalling" in README.md.

### 2.0.0

- **Breaking (internal data model):** chapter sections are no longer a free-text `_hsrtech_section` meta value. They are now rows in a new `hsrtech_sections` database table (`id`, `book_id`, `name`, `description`, `menu_order`), each with its own describable text shown in the table of contents, and chapters reference one via `_hsrtech_section_id`. Existing sites migrate automatically and losslessly on the first request after updating (see `hsrtech_migrate_sections_from_meta()` in `includes/upgrade.php`): every distinct `_hsrtech_section` value per book becomes a section row, and every chapter that had it is repointed at the new row. The table is dropped on uninstall.
- Added a new **Chapterwright → Books & Chapters** admin app (a `@wordpress/components`-based single-page app) for browsing books and managing a book's sections and chapters — adding, reordering, reassigning, and removing — from one screen instead of several scattered post-type screens.
- Added a block-editor sidebar panel ("Book Details" / "Chapter Details") that replaces the old `add_meta_box()` panels, so the same fields are still available when writing a chapter directly in the block editor.
- The Book and Chapter post type list/edit screens no longer appear in the admin menu (`show_in_menu` is now `false`) — the admin app and Settings are the two Chapterwright entries in the sidebar. The screens themselves are unchanged and still load normally when linked to directly.
- Registered a `chapterwright` category and five abilities (list/get/create/delete operations on books, chapters, and sections) with WordPress's Abilities API (6.9+), making the plugin's core operations discoverable and callable by AI agents and automation tools.
- `_hsrtech_subtitle`, `_hsrtech_accent`, `_hsrtech_book_id`, `_hsrtech_order`, and `_hsrtech_section_id` are now registered for the REST API (`register_post_meta()`), and a small `chapterwright/v1` REST namespace was added for sections and bulk chapter reordering — both power the admin app, and both are usable directly by other code.
- Removed `admin/meta-boxes.php` and `admin/chapter-order.php` (superseded by the sidebar panel, REST meta fields, and the admin app's client-side order suggestions).
- Adds a `@wordpress/scripts` build step for `admin/app/src/` only. Every other PHP and JS file in the plugin is unchanged in that respect.

- Added a chapter list with quick-add link to the Book editor, a Book filter on the Chapters list, and automatic chapter-order suggestions.
